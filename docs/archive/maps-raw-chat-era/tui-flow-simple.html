Elgar TUI Flow

A simple map of what happens after you run elgar, open the TUI, type a message, and get a model response.

1. Opening The TUI

CLI start

main.rs

Receives the elgar command. If there are no args and the terminal is interactive, it starts the TUI.

Bridge

terminal_entry.rs

Finds project paths, loads provider config, then calls the TUI crate.

TUI start

terminal.rs

Creates the session and the TUI state box, prints startup text, then enters the input loop.

Input loop

inline.rs

Waits for you to type. When you press Enter, it hands the submitted text to the command parser.

Screen state

shell.rs

Holds the current conversation, input, status, and copy state.

Draw screen

render.rs

Prints the visible state to the terminal.

2. You Type hello

Typed text

inline.rs

Receives hello from the prompt.

Command check

commands.rs

Parses the text as /copy, /clear, /raw, etc. If it is not a known slash command, it becomes normal model text.

Raw chat

raw_chat.rs

Builds one no-tools model request and records start/finish events.

Model call

provider/lm_studio.rs

Sends the active raw request to LM Studio with no tools attached and gets text back.

Official record

session.rs

Stores events and writes JSONL session logs.

Visible update

shell.rs

Consumes the events and updates conversation lines, status, and metrics.

3. What shell.rs Does

It owns TUI state

  • conversation: visible chat lines
  • input: input box state
  • status: ready, working, reply ready
  • copy: copy success/failure message

It does not own commands

  • commands.rs recognizes slash commands.
  • inline.rs decides what happens after a command.
  • shell.rs only performs state actions like copy, clear, show details, or consume model events.

Short version: shell.rs is the screen-side memory of the TUI. It is activated whenever the TUI needs to update or read visible state.

4. Slash Commands

Current live commands

  • /help
  • /clear or /new
  • /cancel
  • /details last
  • /raw <prompt>
  • /copy
  • /copy raw
  • /exit, /quit, /q

Not active now

  • /memory
  • /plan
  • /approve
  • /reject
  • /permissions

5. LM Studio Provider Paths

Active now

  • The harness sends all active model calls through OpenAI-compatible LM Studio chat.
  • harness_tool_decision exposes primitive tool schemas when evidence may be needed.
  • harness_synthesis sends final no-tool synthesis through the same API backend.

Still present, not active

  • provider/lm_studio.rs still has tool-capable request functions.
  • The old action/model-runtime layer that used those tools is archived.
  • So the current TUI does not attach tools.
