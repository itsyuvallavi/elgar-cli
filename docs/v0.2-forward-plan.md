# Elgar v0.2 Forward Plan

This plan starts from the current state: the Core Harness works, the terminal TUI is usable, LM Studio is connected through explicit live mode, and the default test path remains no-network.

## Immediate Fix

1. `ELG-193` Add cancellable LM Studio provider turns.
   - Make timeout/cancel behavior explicit in the provider/controller boundary.
   - A timeout should close the local request path, record a clear provider error, and leave Elgar ready for the next turn.
   - A canceled provider response must not later update visible session output.

2. `ELG-194` Expose `/cancel` during active terminal provider turns.
   - `/cancel` is the typed cancellation command.
   - It must keep textbox/footer visible and return control to the user.
   - It must not mutate controller truth, actions, or files.

## Core

3. `ELG-195` Support model-proposed Markdown `WriteFile` plans.
   - A request like “create an md file with a plan” should become a controller-owned proposal.
   - The model can suggest content, but only the controller creates the action.
   - `/approve` remains required before writing.

## Harness

4. `ELG-196` Add dogfood regressions for live TUI provider flows.
   - Keep `./bin/check-local` no-network.
   - Add scripted coverage for provider success/error, timeout/cancel, `/copy`, `/clear`, `/q`, proposal, reject, and approve.
   - Keep live LM Studio checks manual/optional.

## Window Context

5. `ELG-197` Replace `context: TBD` with controller-backed context accounting.
   - Do not fake token counts, percentages, or model max windows.
   - Show `context: TBD` or `context: unknown` until real metadata exists.
   - Only show values like `128k` when they come from provider/model metadata.

6. `ELG-198` Add context selection and budget trimming policy.
   - Start with local, explicit sources such as `AGENTS.md`, provider config, project metadata, and later selected files.
   - Track included and omitted context.
   - Keep MCP, Skills, and Obsidian out of this slice.

## Performance

7. `ELG-199` Add local performance baselines for TUI, provider, and harness.
   - Measure terminal render/update latency.
   - Measure provider phases where possible: connect, write, first byte/read completion.
   - Track `./bin/check-local` wall time.
   - Do not require live LM Studio for default checks.

## Expanded Permissioned Actions

8. `ELG-216` Implement approved delete, move/rename, and directory actions.
   - Delete, move/rename, and directory creation are explicit permissioned
     actions.
   - Filesystem confirms the real result before the controller records success.
   - Preserve allowed-root, traversal, and symlink safety.

9. `ELG-217` Close the permissioned shell command action model.
   - Keep shell commands high-risk and approval-only.
   - Define command, cwd, timeout, output caps, and environment policy clearly.
   - Keep command data typed and inspectable before execution exists.
   - Policy details live in `docs/permissioned-shell-commands.md`.

10. `ELG-218` Implement approved shell command execution.
    - Shell execution only happens after controller approval.
    - Capture stdout, stderr, exit code, elapsed time, and timeout state.
    - Provider prose must never become command truth.

11. `ELG-219` Add full permissioned capability regression suite.
    - Cover create/edit/overwrite/delete/move/directory and shell lifecycles.
    - Prove rejected actions do not mutate or execute.
    - Prove UI/TUI remains a controller-backed surface.

12. `ELG-224` Review permissioned action completion and decide next roadmap
    slice.
    - Review the implementation against the master plan and roadmaps.
    - Keep extensions deferred.
    - Pick the next small slice: Obsidian read-first memory, expanded-action TUI
      polish, or Core/Harness hardening.

13. `ELG-225` Add read-only local memory context source.
    - Start memory as repo-local Markdown context under `.elgar/memory/*.md`.
    - Keep memory read-only and suggestion-only.
    - Do not add MCP, Skills, Obsidian APIs, or note writes in this slice.
    - Run memory notes through existing context accounting and budget trimming.

- Model suggests.
- User approves.
- Filesystem confirms.
- UI reports.
- Tests protect.
- Extensions wait.
